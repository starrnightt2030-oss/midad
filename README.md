## المميزات
- **شاشة بداية سينمائية** بنغمة مميزة (يمكن إيقاف الصوت من «عن التطبيق»).
- **العوالم**: الحكايات، المعرفة، الروح، الذات، التأملات — كل عالم كوكب والمسموعات تدور حوله، وتنقّل سينمائي بالسحب أو الأسهم.
- **رف ثلاثي الأبعاد** داخل كل عالم، وصفحة لكل عمل بفصوله.
- **مشغّل دائري** يتلوّن بلون العالم: سرعة، تقديم/رجوع، مؤقت نوم، أجواء استماع (موسيقى هادئة، مطر، بحر، ليل).
- **قراءة حية سينمائية**: الكلمة المسموعة تضيء، والسطور تنساب، مع اسم ولون المتحدث.
- **وضع الصفحة**: ورق دافئ، السطر المسموع مظلّل، اضغط سطرًا لسماعه.
- **صانع الخواطر**: حوّل أي سطر إلى بطاقة جميلة وشاركها كصورة.
- **مكتبتي**: أكمل الاستماع، المفضلة، خواطري.
- **تحديثات تلقائية**: المحتوى الجديد يظهر وحده، والإصدار الجديد من التطبيق يظهر في نافذة تحديث أنيقة.

## كيف أضيف محتوى؟

كل الأقسام والقصص تُدار من **لوحة الإدارة** (القسم بالأسفل)، والتطبيق يقرأ من Supabase فقط. ما يظهر في التطبيق هو ما تنشره من اللوحة.

## قاعدة البيانات (Supabase)
التطبيق يقرأ المحتوى من Supabase أولًا، ولو مش متاح يرجع لـ GitHub ثم للنسخة المحفوظة ثم المدمجة.

إعداد لمرة واحدة:
1. افتح مشروع Supabase ← **SQL Editor** ← الصق محتوى [`supabase/migrations/0001_init.sql`](supabase/migrations/0001_init.sql) واضغط **Run**.
2. من **Settings ← API Keys** انسخ مفتاح **service_role / secret**، وضعه في GitHub:
   **Settings ← Secrets and variables ← Actions ← New repository secret** باسم `SUPABASE_SERVICE_ROLE_KEY`.
3. (اختياري) مهمة «مزامنة المحتوى مع Supabase» في تبويب **Actions** تنقل محتوى `content/` يدويًا. المحتوى الحالي تجريبي فلا تُشغَّل تلقائيًا.

طالما قاعدة Supabase فاضية، التطبيق يعرض المحتوى التجريبي من GitHub. أول ما تُنشر قصة من لوحة الإدارة، التطبيق يعرض محتوى Supabase فقط.

## لوحة الإدارة

لوحة ويب في مجلد `admin/` لإدارة كل المحتوى: الأقسام، القصص، الفصول، الأغلفة، الصوت، القفل بالاشتراك، والسماح بالتحميل. تُنشر تلقائيًا على GitHub Pages:
`https://starrnightt2030-oss.github.io/midad/`

**على الموبايل:** نزّل تطبيق «إدارة أثير» من صفحة Releases (الإصدارات التي تبدأ بـ `admin-`) وثبّته، وسجّل الدخول بنفس الحساب.

التجهيز (مرة واحدة):
1. في Supabase ← SQL Editor: شغّل محتوى `supabase/migrations/0002_admin.sql`.
2. في Supabase ← Authentication ← Users ← Add user: أنشئ حسابك (بريد وكلمة مرور، مع Auto Confirm).
3. في GitHub ← Settings ← Pages ← Source: اختر **GitHub Actions**، ثم شغّل workflow «لوحة الإدارة» مرة.
4. افتح اللوحة وسجّل الدخول. **أول حساب يدخل يصبح المدير**، وأي حساب بعده لا يرى شيئًا.

كتابة الفصل: كل سطر جملة. لتحديد متحدث اكتب `الاسم: الكلام`، والسطر بلا اسم للراوي.

## صوتك المسجَّل + ضبط التوقيت تلقائيًا (الطريقة الأساسية)

في الفصل: الصق النص (أو «رفع النص من ملف .txt»)، ثم «رفع صوت» لملف التسجيل (mp3 / m4a / wav)، واحفظ مع «اضبط توقيت النص على الصوت».
العامل على GitHub Actions يسمع الصوت بـ Whisper (مجاني ومفتوح المصدر) ويضبط وقت كل سطر وكلمة على صوتك، خلال دقائق.
زر ⏱ بجانب الفصل يعيد الضبط. ملفات wav تُضغط تلقائيًا إلى m4a لتوفير المساحة. لا يحتاج مفتاح Gemini.

## توليد الصوت بالذكاء الاصطناعي (اختياري)

من محرر القصة في لوحة الإدارة: زر ✨ بجانب الفصل (أو «ولّد صوت الفصل بعد الحفظ» داخل الفصل). اختر صوت كل متحدث من القائمة.
الطلب يُنفَّذ تلقائيًا على GitHub Actions كل ١٠ دقائق (workflow «توليد الصوت»)، ويُرفع الصوت ويتزامن النص سطرًا بسطر.

التجهيز (مرة واحدة):
1. في Supabase ← SQL Editor: شغّل `supabase/migrations/0003_voice.sql` (لازم للطريقتين).
2. في GitHub ← Settings ← Secrets and variables ← Actions: أضف `GEMINI_API_KEY` (مفتاح مجاني من https://aistudio.google.com/apikey).

### تشغيل الطلبات فورًا (مستحسن)
جدولة GitHub «كل ١٠ دقائق» قد تتأخر ساعات. لتبدأ «ضبط التوقيت» و«توليد الصوت» فور الضغط:
1. في GitHub ← Settings ← Developer settings ← Personal access tokens ← **Fine-grained tokens** ← Generate new token:
   - Repository access: **Only select repositories** ← `midad`.
   - Permissions ← Repository permissions ← **Actions: Read and write** (فقط).
   - Expiration: أطول مدة متاحة، وجدّده قبل انتهائه.
2. في Supabase ← SQL Editor: شغّل `supabase/migrations/0005_voice_dispatch.sql`.
3. في SQL Editor نفسه: `select vault.create_secret('github_pat_...', 'github_dispatch_token');` (ضع المفتاح مكان `github_pat_...`).

بعدها أي طلب جديد يبدأ خلال ثوانٍ، ويجهز ضبط التوقيت عادةً في ٣–٥ دقائق. لو المفتاح انتهى أو غير موجود، تعود الجدولة كاحتياطي تلقائيًا.

## الحسابات والاشتراك

- المستمع ينشئ حسابًا من «المزيد ← تسجيل الدخول». القصص المقفولة تعرض شاشة الاشتراك.
- من تطبيق الإدارة ← «المستمعون»: ابحث بالبريد وفعّل الاشتراك (شهر، ٣ شهور، سنة، دائم).
- من «الإعدادات» في اللوحة: السعر ورقم واتساب وطريقة الدفع التي تظهر للمستمعين.
- القصص المسموح بتحميلها يظهر فيها زر «تحميل» للاستماع بدون إنترنت.

التجهيز (مرة واحدة):
1. في Supabase ← SQL Editor: شغّل `supabase/migrations/0004_members.sql`.
2. في Supabase ← Authentication ← Sign In / Providers ← Email: أطفئ **Confirm email** (البريد المجاني في Supabase محدود برسائل قليلة في الساعة).

خطوات النشر على Google Play في [docs/launch.md](docs/launch.md).

## «عوالم أثير» (الأقسام)
16 قسم ثابت المعرّف، لكل قسم صورة ووصف وألوان. من لوحة الإدارة ← «العوالم» تقدر تضيف وتعدّل وترتّب الأقسام، وتغيّر الصورة والألوان، وتخفي القسم من الصفحة أو تعطّله، وتختار لو القسم الفاضي يظهر «قريبًا» أو يختفي. ومن محرّر القصة تقدر تخلي القصة تظهر في أكتر من قسم.

التجهيز (مرة واحدة):
1. الأقسام الـ16 بتتضاف لوحدها من GitHub Actions («أقسام عوالم أثير»)، ولو قسم موجود بنفس الاسم مش بيتكرر.
2. في Supabase ← SQL Editor: شغّل `supabase/migrations/0006_worlds.sql` علشان الوصف والإظهار والربط بأكتر من قسم والأكثر استماعًا. مش بيمسح ولا بيغيّر أي قصة موجودة.

## الإعداد لأول مرة (مرة واحدة)
في المستودع: **Settings ← Secrets and variables ← Actions ← New repository secret**
- `GEMINI_API_KEY` — لتوليد الصوت بالذكاء الاصطناعي فقط (اختياري، من aistudio.google.com).
- `ANDROID_KEYSTORE_B64` — مفتاح التوقيع الثابت (حتى تُثبَّت التحديثات فوق النسخة القديمة).

## الإصدارات والتحديث
- أي تعديل في الكود (`lib/`) يبني APK جديدًا تلقائيًا وينشره في **Releases**.
- لرفع رقم الإصدار عدّل `version:` في `pubspec.yaml` (مثال: `1.1.0+1`).
- التطبيق يتحقق من آخر إصدار عند الفتح ويعرض نافذة «تحديث الآن».
